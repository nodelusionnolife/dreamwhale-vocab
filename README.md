# 梦鲸词汇 · 梦鲸英语对话副本

一个在浏览器里直接打开的独立小站：和「梦鲸」自由对话，她按节奏给你出四级词汇题。
零依赖、无后端、无构建步骤也能跑；API Key 由使用者自己填（BYOK），请求直接发给使用者配置的模型端点。

## 跑起来

```bash
node serve.mjs          # 默认 5173 端口，打开 http://127.0.0.1:5173/
```

也可以直接打开 `dist/dreamwhale-vocab.html`——代码、28 张透明表情与固定头像全部内联。

> 「直接双击（`file://`）打开」预期可用（脚本已全部内联成普通脚本，没有任何模块请求），
> 但这条**只验证过 http 方式**，未在 `file://` 下实测过。

首次打开会让你填「她怎么称呼你」和性别；然后在「设置」里填模型端点、模型名、API Key。
在「个性偏好」中选择 Q 版或立绘版表情；聊天名字旁始终显示同一个萌系头像，选择会保存在当前浏览器中。

## 两种用法

| 形式 | 入口 | 特点 |
|---|---|---|
| 多文件（开发用） | `index.html` | 词库按需加载；改源码刷新即生效 |
| 单文件（分发用） | `dist/dreamwhale-vocab.html` | 图片全部内联，大小以构建日志为准；改源码后要重新打包 |

```bash
npm test                # 旧行为检查 + 请求、上下文、存储、实际构建回归，零依赖
npm run build:single    # 重新打包单文件 → dist/dreamwhale-vocab.html
```

## 它是怎么工作的

**代码负责选题和出题节奏，模型负责在对话中判断作答。** 每 N 条角色回复，代码从内置题库里抽一道题，
把题目用 `<Question>` 包起来注入这一轮的用户消息；答案以 `<AnswerKey>` 附作模型参考，要求不直接泄露。
这些标签是提示词约定，不是访问权限。用户原文和应用注入分开保存，题干与答案在该轮发送时冻结。

```
src/content/   内容层：人设、提示词、文风规则、表情表、词汇表、题库、梗表
src/app/       应用层：准备用户回合、生成回复；通过参数替换模型调用以便离线验证
src/engine/    引擎层：出题节奏、会话状态、提示词编译、限额裁剪、用量归一化、资产解析
src/gateway/   网关层：OpenAI 兼容调用、地址归一化、超时、取消、响应校验
src/storage/   存储层：localStorage 读写、快照冲突检查、分段暂存后提交索引
src/platform/  平台层：本地媒体地址解析（多文件版给相对路径，单文件版查内联映射表）
src/ui/        渲染层：模型正文用 DOM 文本节点显示
src/main.js    页面入口：事件、设置、两种玩法和渲染连接
assets/        素材：mengjing/ 中保存两套透明表情与固定头像
tools/         零依赖打包器 + 词库生成 + 抽查脚本
```

几个刻意的设计：

- **固定规则在前，用户档案在后**；日常发送只追加历史。动态休息计数不进入系统提示词。
- **每轮回复附带 20–50 字小总结**，用 `<TurnSummary>` 包裹，平时隐藏。调试模式显示全部小总结；已裁剪回合直接显示小总结。
- **超限时按完整问答回合裁剪正文**，小总结持久保留并继续发送给模型。最新题目另留参考快照。关闭裁剪只停止后续裁剪，不能恢复已删除正文。
- **没有有效小总结的旧回合保留正文**。总结和必要资料全部计入 token 预算；超出预算时提示调整上限或新建会话，不自动丢弃总结。
- **先编译，再估算，再请求**：题干、答案和省略说明都计入输入估算；默认预留最多 2,048 token 供回复，且不超过总预算的四分之一。
- **失败只重试同一条待回应消息**，不重复抽题、扣休息轮次或追加原文。保存失败时不会清空待发输入。
- **未知用量保持未知**。缓存比率只用确实同时报告了输入量与缓存量的轮次计算；实际命中率以供应商返回的 usage 为准。
- **图片绝不进消息、绝不进 localStorage**，消息里只存「键」。表情与头像读取本地文件，单文件版使用内联图片；页面背景使用渐变色。
- **外观选择只影响显示**，两套表情共用同一组情绪标签，切换风格不会改变消息或模型提示词。
- **零依赖**：没有 bundler、没有运行时库，`tools/build-single-html.mjs` 是自己写的打包器。

存储 v3 可以读取旧版会话，首次成功保存时升级。消息内容和会话记录先写入新位置，最后更新索引；失败保留旧记录。
旧客户端不识别 v3，升级后的浏览器数据不宜直接交给旧代码。多标签页采用乐观冲突检查，不提供数据库级同时写入事务。

## 改提示词

界面里没有提示词编辑框，提示词是源码里的常量：

| 想改什么 | 改哪里 |
|---|---|
| 人设、四类标记格式、题目机制、自攻击清单 | `src/content/chat.js` |
| 禁词表、文风规范、认知边界 | `src/content/style.js`（两个模式共用） |
| 出题与判定（拼单词模式） | `src/content/prompts.js` |
| 表情标签与别名（提示词里的可用列表由它生成） | `src/content/emotions.js` |
| 题库 | `src/content/cet4-questions.js` |

改完源码：多文件版刷新即可；单文件版要重跑 `npm run build:single`。

## 素材与生成脚本

两套表情分别放在 `assets/mengjing/chibi/` 和 `assets/mengjing/portrait/`，每套 14 张透明 WebP；固定头像为 `assets/mengjing/avatar.webp`。打包时全部内联进单文件。

Remit.ee 图床直链登记在 `assets/mengjing/hosting.json`，包含 29 张图片的本地路径、直链、预览页和 SHA-256 校验值。

```bash
node tools/build-cet4.mjs     # 从 tools/raw/ 的词表生成 src/content/cet4.js
```

原始词表没有随仓库提供；重新生成前需要自行准备。已有生成词库可直接运行。

表情标签和文件名登记在 `src/content/emotions.js`，文件大小及校验值登记在 `src/content/assets.js`。
增加表情时需补齐两套图片和对应登记；提示词里的可用列表由表情表生成。

## 使用前请知悉

**模型与费用**：需要自备 OpenAI 兼容端点与 Key。Key 只存在你自己的浏览器里。
每轮发送保留的正文、小总结与必要题目资料。关闭正文裁剪仍检查上下文预算；小总结会随轮数增长。
目前使用 Chat Completions 协议及 `max_tokens`；只接受其他协议或 `max_completion_tokens` 的模型需要对应适配。
拼词模式的普通 assistant 预填充不等同于供应商专用的强制前缀续写。

**素材来源**：

- 梦鲸的两套表情与固定头像根据项目角色参考图使用 AI 生成，随项目以本地图片分发。
- `src/content/cet4.js` 由 `tools/build-cet4.mjs` 从 `tools/raw/` 的两份词表生成。
  那两份词表是对公开数据（四级考试大纲词表、COCA 词频表）的筛选整合，
  **再分发前请自行确认上游的权利状态**。
- 题库 `src/content/cet4-questions.js` 为本项目原创。
